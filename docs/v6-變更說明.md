# v6.0 變更說明（2026-09-29）

依據 Claude Doc「實驗計畫：行為導向版（v6 草案）」。v6.0 以 v5.12 為基礎，階梯、閘門、P1／P3／P4 提示詞、取消選取都沒有改。

## 流程

| 關卡 | 內容 | 時間上限 |
|---|---|---|
| S0 | 同意書、基本資料 | 10 分 |
| S1 | 前測 8 題選擇題（汰侈 2），用來分層 | 6 分 |
| S1b | 基線行為：汰侈 11，逐句翻譯 3 句，可按提示／解釋／跳過 | 10 分 |
| S2 | 訓練 3 篇：汰侈 3＋8、汰侈 5、汰侈 6；每篇至少 180 秒、最多 8 分鐘 | 每篇 8 分 |
| S4 | 認知負荷量表 | 2 分 |
| S5b | 表現：儉嗇 1 逐句翻譯 4 句（沒有求助按鈕），接著儉嗇 9 字詞選擇題 5 題 | 12 分 |
| S5a | 行為：儉嗇 7 逐句翻譯 3 句，可按提示／解釋／跳過 | 10 分 |

S3（即時測驗）和 S6（延遲測驗）已從流程移除。

## S2 的改變

- 每篇有 2 句**必做目標句**，三組都會看到底色。
- 提問式組和直答式組要把 2 句都走到解釋、按「看完了」，「下一篇」才會解鎖；無 AI 組只讀，不用寫譯文。
- 開放作答的理由在同一層被退回 2 次後，第 3 次強制接受，並記錄 `reason_forced`（D7）。
- 每筆對話紀錄都帶 `passageId`。

## 行為指標怎麼記

每一句翻譯存成 `translations` 表的一列：

| 欄位 | 意義 |
|---|---|
| `triedFirst` | **主要結果**。第一次按提示／解釋／跳過時，作答框已有至少 2 個漢字；沒求助就看送出的內容 |
| `firstHelpKind` | 第一個按的是 hint（工具性）、explanation（執行性）還是 skip |
| `firstHelpMs` | 句子出現到第一次求助的毫秒數（伺服器計時）；過快求助在分析時用 10 秒切 |
| `draftAtFirstHelp` | 第一次求助當下作答框的內容 |
| `firstInputMs` | 句子出現到第一次按鍵（瀏覽器回報） |
| `hintMs`／`explanationMs` | 打開提示、解釋的時間點 |
| `text`、`skipped`、`timedOut` | 最終作答；照抄程度用 `text` 對解釋文字計算 |

門檻在 `src/lib/config.ts` 的 `CONFIG.translation`，試跑後、正式收案前凍結。

## 評分（離線）

```bash
npm run db:dump                                                   # 產生 backups/<時間>/translations.json
npx tsx scripts/blind-sheet.ts backups/<時間>/translations.json --sample 0.25   # 人工盲評用
npx tsx scripts/grade.ts backups/<時間>/translations.json --run 1              # LLM 評分
npx tsx scripts/grade.ts backups/<時間>/translations.json --run 2              # 自我一致性
npx tsx scripts/agreement.ts --a grades-run1.csv --b grades-run2.csv
npx tsx scripts/agreement.ts --a rater1.csv --a-key key.csv --b grades-run1.csv
```

- 評分只看三個得分點（A 關鍵字詞、B 誰對誰、C 前後關係），每點 0／1。
- 給 1 分時，模型必須引用受試者譯文裡的字，否則那一筆重試，仍不行就標為 failed。
- 送給模型的資料不含組別和受試者 ID，順序也打亂。
- 合格標準（計畫第 6 節）：模型對人的 κ 不低於人對人的 κ 減 0.10，而且至少 0.60。
