# 程式與提示詞審閱指南

更新日期：2026-09-27（v5.8 開放作答）。對象：研究者 WCC。這是研究工具的審閱文件，不是已證實教學有效的宣稱。

閱讀順序：先讀第 1–5 節，理解不同組別實際接收什麼；再讀第 6–8 節，檢查提示詞的限制與文獻；最後依第 9 節檢查程式。介面操作另見 [介面測試指南](介面測試指南.md)，部署另見 [後端部署與驗證](後端部署與驗證.md)。

## 1. 先確認研究在比較什麼

現行專案是文言文閱讀的三組隨機分派先導研究：提問式協助、直答式協助、無 AI 協助。AGENTS.md 記載計畫 N = 45，每組 15 人。程式依前測分層，在各層人數最少的組別間隨機分派；**並未實作全研究滿 45 人或每組滿 15 人即停止收案的招募上限**。

重點不是做一個什麼都能回答的聊天機器人，而是比較不同協助方式下的閱讀、後續無 AI 測驗、使用行為與可行性。使用協助是自願的；同樣有 180 秒最低閱讀時間，不等於實際閱讀時長或協助劑量相同。

| 階段 | 內容 | 模型是否介入 |
|---|---|---|
| S0 | 說明、同意與基本資料 | 否 |
| S1 | 前測，8 題；之後分層分組 | 否，固定答案計分 |
| S2 | 學習篇章、註解、依組別提供協助 | 只有兩個 AI 組的部分路徑 |
| S3 | 閱讀後測驗 1／2：同篇立即理解，10 題 | 否；可看原文，不顯示註解 |
| S4 | Klepsch 等人八題多向度認知負荷量表；緊接 S2、先於 S3 | 否 |
| S5 | 閱讀後測驗 2／2：新篇遷移，12 題；主要結果 | 否 |
| S6 | 主流程完成後 +24 至 +48 小時內，另一篇章，10 題 | 否 |

S4 是依 Klepsch 等人（2017）製作的八題繁體中文研究翻譯，分開計算內在、外在與增生認知負荷，**不能稱為 NASA-TLX（NASA Task Load Index，工作負荷量表）**。來源、題目及計分見 `docs/認知負荷量表.md`。S3 也不是「邊用 AI 邊考試」；協助只在 S2。

### 附件不是現行程式規格

| 資料 | 如何使用 |
|---|---|
| 下載的 HTML、兩個 JSX 示範 | 理解早期互動構想；不是現在的後端、保密或分組實作 |

## 2. 三組的提示詞：先看這張表

「提示詞」是送給大型語言模型（Large Language Model，LLM）的指示。固定教材不經生成，因此即使畫面長得像 AI 對話，也不代表每一則都呼叫模型。

| 情境 | 提問組 `socratic` | 直答組 `direct` | 無 AI 組 `control` |
|---|---|---|---|
| 選到目標句或其重疊範圍 | 前兩層用預寫開放式觀察題，第三層問理解；每層自行寫答案與理由 | 立即顯示預寫解釋 | 不生成回覆 |
| 選到非目標範圍 | 多字時由讀者自行輸入焦點，再由模型生成前兩層開放式觀察題 | 模型直接生成短解釋 | 不生成回覆 |
| 判斷答案正誤 | 新流程不在互動中判正誤；有理由但答錯仍進下一層 | 沒有作答要求 | 沒有作答要求 |
| 判斷理由 | 規則先判；未定時才請模型判「有沒有理由」 | 不適用 | 不適用 |
| 決定何時給解釋 | 伺服器階梯 | 選取後立即 | 不適用 |
| 目標句最後解釋 | `target.explanation` | 同一個 `target.explanation` | 不適用 |

先打開這三個檔案：

1. [prompts.ts](../src/lib/prompts.ts)：模型收到的系統指示與每次輸入模板。
2. [passages.ts](../src/content/passages.ts)：四個目標句的固定問題與解釋；舊選項欄位僅供既有互動恢復。
3. [engine.ts](../src/lib/engine.ts)：決定某次互動究竟使用固定教材、呼叫模型，還是回退。

只讀 `prompts.ts` 不足以知道受試者實際看到什麼。

### 不花模型費用，列出實際提示詞

在專案根目錄執行：

```powershell
npm run prompts:inspect -- 帝甚不平
npm run prompts:inspect -- 擊之
```

第一條示範自由選取：列出提問組 system、第一與第二層 user，以及直答組 system/user。第二條命中 TS1：列出固定教材，並標示 `generated: false`。

如果相同字出現不只一次，可加第三個參數指定零起算文字位置，例如 `npm run prompts:inspect -- 之 位置數字`。程式會拒絕不吻合的位置。位置以 JavaScript 的 UTF-16 單位計數，終點不含在範圍內。

這個工具不送模型請求、不輸出金鑰。**它會輸出研究者用固定解釋，不要把輸出交給受試者或放在公開網頁。**

## 3. 提問組：逐段理解提示詞

### 3.0 多字自由選取先確認焦點

非目標範圍含多個字時，介面只問「你主要想問哪個字或詞」；讀者自行輸入反白範圍內的連續字詞。新流程不產生候選選項。

原始反白不會被覆寫。`ActiveInteraction.selection` 保留原範圍，`focusSelection` 記錄讀者指定的焦點；`focus_selected` 事件記錄輸入結果。重整頁面會恢復焦點輸入步驟。

目標句不走焦點生成，仍使用預寫階梯與兩組逐字相同的最終解釋。這個例外用來保留研究操弄的不變條件，不代表介面能自由回答目標句內的每一個字。

舊版候選生成與回退函式仍保留供舊互動使用，但 v5.8 新互動不呼叫。

### 3.1 System 與 user 分別負責什麼

`socraticOpenSystemPrompt()` 是 v5.8 每次生成的固定規則：角色、禁令、範圍、策略、只輸出一個開放問題的 JSON 格式。

`socraticTurnPrompt()` 提供本次資料：完整學習原文、選取文字、粒度標記、位置、前一句／所在句／後一句，以及目前是第 1 或第 2 層。

完整原文是 S2 學習篇章，不是 S1/S3/S5/S6 題庫。不要為了「回答更準」把測驗答案加入上下文，否則會污染測量。

第二層會收到上一輪的答案與理由，但不會收到完整對話歷史，也沒有完整的學生狀態分類器。這是有限上下文的分層生成，不是完整多輪診斷式家教。

### 3.2 禁令的目的與執行邊界

| 指示 | 研究用途 | 程式真正檢查到哪裡 |
|---|---|---|
| 不翻譯、不直接說字義 | 避免提問組提前接受直答處理 | 搜尋有限禁語；無法窮盡所有意譯 |
| 不自問自答 | 保留讀者嘗試 | 沒有完整語義判別器 |
| 不問含答案的是非題 | 避免問號包裝的答案 | 含特定是非詞且有問號即攔截，可能誤擋中性問題 |
| 不教指定語法術語 | 將操作集中在文本線索 | 檢查一份有限術語表；不是禁止所有語言學用詞 |
| 不自行决定提供答案 | 保持操弄順序 | 階梯掌握正式解釋出口；生成文字仍須洩答檢查 |
| 多字選取不稱「這個字」 | 避免指稱不清 | 非單字問題含「這個字」會被攔截 |
| 必要時引述鄰句 | 自由選取也能回到語境 | 有提供鄰句，但沒有自動證明引用足夠或正確 |
| 第一、二層只問觀察 | 區分線索辨識與解答 | 結構與字串檢查；另攔截「後面接什麼」等相鄰字抄寫題，不等於完整語義品質驗證 |

不要把「prompt 寫了不得洩答」寫成「模型不會洩答」。本專案有多層攔截，但仍需要人工檢視送達的題目。

### 3.3 四類策略 A–D

目前字串：

```text
A 你用了哪個線索？還有沒有第二個線索可以對照？
B 把你的解釋代回整句，通順嗎？哪裡卡住？
C 這個字在句子什麼位置？前後是什麼詞性？
D 如果這是白話文，你會怎麼判斷？同樣方法用在這裡呢？
```

這四句是本專案的中文設計，不是四句已核實的論文原文翻譯。策略意圖分別是多線索、語境檢核、位置線索與白話遷移。

審閱時必須看到內在張力：A 有「有沒有」而洩答檢查可能攔截；B/D 接近解釋或白話轉換，而前兩層應只觀察；C 預設單字選取且提到詞性。現在指示明訂「適用時才用，禁令優先」，不是每次逐字使用。

因此 `strategy: A/B/C/D` 是生成者提供的標籤，不是已由外部評分者確認的策略分類。統計前要人工核對。

### 3.4 結構化輸出

模型被要求輸出 JSON（JavaScript Object Notation，可由程式解析的資料格式）：

```json
{
  "type": "question",
  "strategy": "A",
  "text": "對照所選文字與前後文，你看到哪些可以互相檢查的線索？"
}
```

- `text` 是顯示的開放式問題；`strategy` 只供紀錄，不控制階梯。
- 不得回傳 `options` 或 `answerIndex`；一旦出現就重試或回退。
- 程式核對 `type` 與問句格式，但是否開放解釋仍由伺服器狀態機決定。

沒有模型提供的答案索引。伺服器只判斷理由是否有內容，不判讀者答案真偽；生成問題的語義與洩答風險仍需人工稽核。

### 3.5 生成失敗、重試與回退

```text
生成 → 解析、問句格式及洩答檢查、禁止選項與答案索引
     ├─ 通過 → 顯示並儲存
     └─ 不通過 → 再生成一次
                   ├─ 通過 → 顯示，紀錄 regenerated
                   └─ 不通過 → 固定開放觀察題，degraded=true
```

新流程沒有選項或「提早答對」出口；三層作答並說理後才取得解釋。兩次生成的回應與旗標會保留，供研究者稽核。

傳輸層另有一次重試：每次請求最多 20 秒，最多兩次。因而一次自由選取生成，在最壞的失敗路徑可有四次底層請求；若同一輪先做理由模型判定，還會增加該判定的時間。不要把「重試一次」誤解成整段互動只會呼叫模型兩次。

## 4. 解釋何時出現：不是提示詞決定

打開 [ladder.ts](../src/lib/ladder.ts)，看 `reduce()`，再對照 `Engine.reply()`。

```text
第 1 層：自行寫答案 + 有內容的理由 → 第 2 層
第 2 層：自行寫答案 + 有內容的理由 → 第 3 層
第 3 層：自行寫答案 + 有內容的理由 → 解釋
答案對錯不改變階梯長度；理由未通過則留在當層重答
顯示解釋後 → 點「看完了」→ 結束本次互動
```

新流程不使用舊版選擇題的退回上限。模型理由判定失敗時，新流程退回重答，舊選擇題互動仍採 fail-open；第三層是開放式理解題，不是給答案的選擇題。

### 4.1 理由模型不是正誤評分者

`reasonJudgePrompt()` 的核心是：判斷「有沒有給出理由」，**不判理由對不對**。

接受條件包含引用文字／位置、因果、比較；推論錯誤但有理由仍可接受。先由 `ruleCheckReason()` 處理明確情況，未定時才呼叫模型。

目前規則的重要限制：

1. 去除標點後少於 4 字退回。
2. 空白、無內容短語會退回；舊互動還會檢查是否只重述選項。
3. 至少 4 字、與原句共享一個字，就可能以 `quotes_text` 接受。這是寬鬆啟發式，**不是實質引用或推理品質的證明**。
4. 含部分因果連接詞也可能直接接受。
5. 模型請求失敗、無有效判定時，新開放作答流程不放行；舊選擇題互動維持 fail-open（失敗時放行）。`reason_judgement` 用 `modelFailed` 標記判定失敗、`failOpen` 標記失敗後放行，`accepted` 記錄實際結果。

`answerJudgePrompt()` 是舊版答案比對器。v5.8 新互動不呼叫它；答案即使錯誤也會在理由通過後進下一層。

### 4.2 舊版退回上限與新版差異

舊版選擇題互動保留原本 `>= 2` 的強制放行路徑，供進行中的舊工作階段恢復。v5.8 新互動不因重複填「猜的」而前進；研究方法應明確記載此版別差異。

## 5. 直答組與無 AI 組

### 5.1 直答組的 system prompt

`directSystemPrompt()` 要求：只解釋所選範圍、不輸出整篇翻譯、每則不超過 60 字、不提問、不要求作答；允許語法術語。

依標記 `word/sentence/passage` 提供字義、句意或段意。現行粒度是單字／非跨句多字／跨句，不是早期「四字以下都是詞」；選取不會被自動擴成整句。

`directTurnPrompt()` 傳完整 S2 原文、原始選取與粒度，不附測驗答案。目標句則直接走預寫解釋，不呼叫這個 prompt。

生成文字會先檢查字數與粗略的整篇覆蓋，再生成一次或回退。但「不能提問」「只解釋選取」「註解範圍轉介」目前主要仍是提示詞限制；沒有完整語義檢查。

### 5.2 兩組相同與不同的邊界

相同的是供應商、模型設定來源 `CONFIG.llm`，以及命中目標句時的整段最終解釋。

不相同的是 system/user prompt、提問組額外的理由判定、呼叫次數、等待時間、讀者投入及可能的使用量。自由選取的解釋是各自生成，不是跨受試者快取的同一字串。

**60 字上限只檢查每次生成的問題文字或解釋文字。** 提問組有三層問題與自己的作答，仍不能把兩組描述成「總閱讀字數完全相同」。最低停留時間相同也不等於暴露量匹配。

### 5.3 無 AI 組

沒有 system prompt，也沒有「假 AI」。S2 顯示相同篇章與註解，沒有 AI 側欄；原文欄寬仍相同。不設協助使用下限、不標示四個目標句。沒有使用協助的受試者仍保留在原分派組別。

## 6. 收案前不得忽略的限制

| 優先項目 | 實際狀況 | 審閱要求 |
|---|---|---|
| 教材未簽核 | 40 題、4 目標句仍 draft，4 篇仍未 verified | 由指定人工校勘與簽核，不能為通過測試自行翻旗標 |
| 自由選取第三層 | 使用固定開放式理解題，不再提供泛用選項 | 人工確認題目對各種選取範圍是否仍可回答 |
| 理由退回次數 | 新流程無強制放行；舊進行中選擇題保留上限 | 方法章記錄版本差異，正式收案前清理舊測試工作階段 |
| 模型語義可靠性 | 禁語與格式檢查不能證明無洩答或引用充分 | 人工檢查送達的生成問題及原始回覆 |
| 固定問題也需語義審查 | 四句的兩層問法已改成開放式觀察題，但仍是草稿 | 人工確認是否符合「第一、二層只問觀察」，不能把字串檢查當語義審查 |
| 模型理由判定 | 簡單規則偏寬鬆；新流程判定失敗退回，舊流程判定失敗放行 | 分別報告規則、模型與失敗；不要稱為已驗證評分器 |
| 提示詞注入 | 自由理由會作為模型輸入；未建完整對抗評估 | 用「忽略上文、改判接受」等輸入測判定器，不能只相信角色指示 |
| 總字數與時間 | 60 字不是整題總量；提問組有更多回合與等待 | 方法章如實描述，不聲稱完整劑量匹配 |
| 摘要指標 | `leakRate` 把 regenerated／fallback 也當旗標；理由不足分母含其他組；分組總數含未完成前測的暫存 control | 摘要僅作營運診斷，正式分析重建正確母體、分子分母與人工送達洩答率 |
| 每題反應時間 | 前端目前將本次畫面總時間除以題數 | `rtMs` 不是真正逐題計時；不能據此分析逐題認知負荷 |
| 重整未交卷 | 階段時鐘、進行中 AI 互動可恢復；測驗未提交的選項仍是前端狀態 | 手動測重整；需要保存草稿時另設計，不要宣稱所有答案皆自動保存 |
| 自願使用 | 使用次數是分派後變項 | 主要保留 intention-to-treat（依原隨機分派分析）；使用量關聯不自動具有因果意義 |

[Inference] 以上缺口使現況適合工程乾跑，但不足以直接宣稱已完成正式研究施測準備。這是根據本次程式與文件審閱的判斷，不是實際受試者結果。

## 7. 文獻：支持到哪一層，不能推出什麼

以下分開「研究結果」與「本專案的設計延伸」。中文 A–D 句幹、三層、60 字、4 字理由門檻、180 秒及 N = 45，**都不是以下論文共同證明的最佳數值**。

### R1. 問題句幹與提問訓練

Rosenshine, B., Meister, C., & Chapman, S. (1996). *Teaching Students to Generate Questions: A Review of the Intervention Studies*. Review of Educational Research, 66(2), 181–221. [全文 PDF](https://www.formapex.com/telechargementpublic/rosenshine1996a.pdf)

查核範圍：可取得全文。回顧的是教學生「產生問題」。文中自編測驗與標準化測驗的結果不同，不能將特定子類型的 1.12 效果量套成此 AI 提問介面的預期成效。

[Inference] 本專案借用結構化提示的想法；學生自己生成問題與被 AI 問問題不是同一操弄。支持設計靈感，不直接支持 A–D 四句或此介面的效果。

### R2. 閱讀澄清策略

Palincsar, A. S., & Brown, A. L. (1984). *Reciprocal Teaching of Comprehension-Fostering and Comprehension-Monitoring Activities*. Cognition and Instruction, 1(2), 117–175. [全文 PDF](https://images.scholastic.co.uk/assets/a/d6/6f/palincsar-reciprocal-teaching-1619152.pdf)

查核範圍：可取得全文。相互教學包含摘要、提問、澄清、預測等組合策略。

[Inference] 可作為「遇到不理解處，回到文本澄清」的概念來源；不能據此宣稱只留下 AI 澄清問題也有相同結果。

### R3. 最後提示與避免卡住

Aleven et al. (2016). *Help Helps, But Only So Much: Research on Help Seeking with Intelligent Tutoring Systems*. International Journal of Artificial Intelligence in Education, 26, 205–223. [作者提供全文](https://www.cs.cmu.edu/~aleven/Papers/2016/Aleven_etal_IJAIED2016-Helpseeking.pdf)

查核範圍：可取得全文。討論智慧教學系統的求助、提示及最後提示，亦指出幫助使用與學習的關係有條件，並非提供提示必然提升學習。

[Inference] 支持檢查提示階梯是否讓讀者有路可走；不直接支持本專案固定三層或其退回規則。

### R4. 先嘗試再接受資訊

Kornell, N., Hays, M. J., & Bjork, R. A. (2009). *Unsuccessful Retrieval Attempts Enhance Subsequent Learning*. Journal of Experimental Psychology: Learning, Memory, and Cognition, 35(4), 989–998. [作者提供全文](https://web.williams.edu/Psychology/Faculty/Kornell/Publications/Kornell.Hays.Bjork.2009.pdf)

查核範圍：可取得全文。研究包括先嘗試檢索、之後獲得正確資訊的學習情境。

[Inference] 可作為「先試再看說明」的機制假設；不能等同證明文言文開放作答加理由會產生相同效益，也不能推論越挫折越有效。

### R5. 解題後教學與 productive failure

Sinha, T., & Kapur, M. (2021). *When Problem Solving Followed by Instruction Works: Evidence for Productive Failure*. Review of Educational Research, 91(5), 761–798. [出版頁](https://journals.sagepub.com/doi/10.3102/00346543211019105)

查核範圍：出版摘要及可取得出版 PDF。整體統合包含 53 項研究、166 個比較，先解題後教學相對反向安排的整體效果量 g = 0.36；不是只針對本專案的概念題或遷移題。

[Inference] 先嘗試後教學具有研究依據，但成效依設計與情境而變，不能把本專案任何「先問後答」都稱為已驗證的 productive failure。

### R6. 為何要求理由

Bisra, K., Liu, Q., Nesbit, J. C., Salimi, F., & Winne, P. H. (2018). *Inducing Self-Explanation: a Meta-Analysis*. Educational Psychology Review, 30, 703–725. [出版摘要](https://link.springer.com/article/10.1007/s10648-018-9434-x)

查核範圍：已核對出版摘要；**未取得付費全文**。摘要報告 64 份研究報告、69 個效果量，整體加權 g = .55。

[Inference] 支持要求自我解釋的方向，不支持「只要四字、出現因為、共享一個字就算充分理由」。目前理由把關的操作定義與自我解釋品質之間仍需驗證。

### R7. 為何不能只看有 AI 時的作答表現

Bastani et al. (2025). *Generative AI without guardrails can harm learning: Evidence from high school mathematics*. Proceedings of the National Academy of Sciences, 122(26), e2422633122. [DOI／出版來源](https://doi.org/10.1073/pnas.2422633122)

查核範圍：核對正式出版資訊與結果摘要。研究場景是高中數學；練習表現改善不代表撤去 AI 後表現也改善。

[Inference] 這支持另外量測無 AI 時表現的必要性，不證明本研究的直答組一定造成傷害。原提示詞註解對更正公告的額外說法沒有在此作為論據。

### R8. 文言文閱讀困難的情境依據

劉潔玲、谷屹欣（2017）。〈香港高中學生閱讀文言文的表現與困難〉。《教育學報》，45(2)，161–181。[期刊提供 PDF](https://hkier.cuhk.edu.hk/en/publications/ej-v45n2-161-181)

查核範圍：PDF 內頁題名與內容；連結頁面的索引標題與 PDF 題名有不一致，引用以 PDF 內文為準。研究涉及 454 名中四學生及 48 人訪談。

[Inference] 可支持文言文閱讀與字詞理解困難的問題背景，不能當成「禁止語法術語能提升學習」的實驗證據。原程式的一句未核實直接引文已移除，不應再當逐字引用。

### 如何寫進論文方法章

可以寫：「設計參考提問訓練、自我解釋、先嘗試後教學及提示階梯研究，再依文言文情境操作化；其在本情境的可行性與效果由先導研究探索。」

不應寫：「文獻證明這套三層 prompt 最有效」「g = .55 所以本研究預期提升 55%」「模型通過了 regex 所以沒有洩答」。效果量 g 不是百分比；規則檢查通過也不是語義品質認證。

## 8. 修改提示詞的審閱流程

1. 先說明改的是措辭、任務要求、層級內容、回退還是模型參數。後四者可能改變研究操弄。
2. 分開檢查命中目標句與自由選取；同一改動不一定影響兩者。
3. 用 `prompts:inspect` 保留送出的 system/user，並以明確版本或 Git commit 識別；`CONFIG.version = v5.8` 本身仍不足以區分所有歷史修改。
4. 離線先跑測試，檢查缺理由、答錯但有理由、過長回應、模型輸出選項、模型失敗與重整。
5. 正式模型另在測試資料庫試單字、多字、跨句、重複字、非目標片語、理由注入；不要用 mock 的表現當模型品質證據。
6. 稽核每個送達的問句：有無提前透露意義、是否要求實際判斷、引用是否真在文中、粒度指稱是否清楚、第二層是否換了線索。
7. 若改變學習內容／方法，先更新研究決策與教材簽核，再更新測試。不要只修改測試讓程式變綠。
8. 收案開始後凍結模型、提示詞、教材與分層切點；需要變更時分批標記，不把不同版本混成同一处理。

`interactions` 可查顯示文字、原始回應、延遲與回退；v5.8 新互動不存生成選項或答案索引。`events.reason_judgement` 可查理由判定來源與失敗放行。傳輸層內第一次失敗的完整 HTTP 回應並未逐次完整保存；目前仍不是每個底層請求的全量追蹤系統。

### 後端的責任分界

```text
受試者瀏覽器
  → API：輸入、token、階段與時限驗證
    → study：流程與分組
      → engine：固定教材／提示詞／模型／階梯／紀錄
        → Store 交易
          → 開發：本機 JSON
          → 部署：Supabase PostgreSQL
```

PostgreSQL 是關聯式資料庫。交易讓一次請求的作答、事件及階段更新一起成功或一起回復；分組另鎖一個共用資料列，使讀取各組人数與分派不互相穿插。模型請求期間仍持有該受試者資料列的鎖，這提高狀態一致性，但增加資料庫連線占用與等待成本，尚未完成真實多人負載測試。

RLS（Row Level Security，資料列層級安全性）已啟用且未開放瀏覽器存取政策。此實作由伺服器持有資料庫連線，不是讓前端用 Supabase 公開金鑰直接讀研究表。受試者回應透過欄位白名單塑形，資料庫原始列不可直接回傳。

版本欄位與設定快照只記錄已儲存的資訊，不會自動證明後續部署從未變更。部署版本、提示詞及教材仍需研究者封存。
