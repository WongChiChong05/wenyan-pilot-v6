# 介面測試指南

首頁測試必須確認年齡、性別、主修／系所與電郵未填時不能開始；年齡只接受 16 至 80 的整數。成功建立工作階段後，電郵只應出現在 `wenyan.participant_contacts`，不得出現在 `participants.demographics`。

先讀 [程式與提示詞審閱指南第 2 節](程式與提示詞審閱指南.md#2-三組的提示詞先看這張表)。先理解各組操作，再測畫面；不要拿示範模型評估教學品質。

## 1. 安全的本機示範

在專案根目錄開 PowerShell，使用專用示範資料，不接正式 Supabase、不花模型費用：

```powershell
$env:DATABASE_URL = ''
$env:DATA_FILE = './tmp/interface-demo/db.json'
$env:LLM_PROVIDER = 'mock'
$env:STUDY_MODE = 'dry-run'
npm run demo:seed
npm run dev
```

保持這個視窗開著。若已有開發伺服器，先在原視窗按 Ctrl+C 停止自己啟動的伺服器，再執行以上指令，不要同時讓兩個程序操作同一個 JSON 檔。

`demo:seed` 每次新增六位假受試者，不清空既有資料：三組各有一個 S2 閱讀連結與一個 S6 延遲測驗連結。連結直接顯示在終端機。S6 假資料設定為 25 小時前完成主流程，不改動正式時間限制。

如果系統已有 `.env.local` 的真實資料庫設定，以上環境變數應在**同一個** PowerShell 視窗設定並啟動，避免誤接正式資料。假資料不要匯入研究資料庫。S2 時鐘從建立假受試者時開始；建立後超過 14 分鐘就重跑種子工具，使用新的連結。

`mock` 是固定邏輯的示範供應商，不是真實模型。自由選取的直答說明會標記「示範模式：未接上模型」；固定目標句仍顯示真正的預寫教材，因此不會每一句都出現示範字樣。

## 2. 先測三組的差異

### 提問組連結：`socratic S2`

1. 進入全螢幕，確認原文沒有標出哪四句是目標句。
2. 拖選「擊之」。這會命中 TS1，不應讓模型現編題目；畫面應顯示預寫觀察題、答案欄與理由欄，沒有選項。
3. 答案填「我認為是後面的字」，理由填「感覺」。第一次應要求補充理由，不應直接開解釋。
4. 重新輸入答案與有依據的理由，例如「因為前面寫了鐵如意」。即使答案不正確，只要有理由也應進入下一層；完整三層後才顯示解釋。
5. 到解釋時，對照 `passages.ts` 的 TS1 `explanation`，應逐字相同。
6. 未點「看完了」之前，另拖一段不能把原互動悄悄取代。點完後才能開下一次互動。
7. 再選「帝甚不平」，自行輸入想問的字詞「不平」，再檢查自由選取的開放題。這次走 mock 生成路徑，不代表這組生成題的語義已經合格。
8. 在提問中途重新整理，確認目前問題與選取範圍恢復，不能因重整直接跳到解釋。

`npm run prompts:inspect -- 擊之` 可檢查三層實際提問文字與理由判斷 prompt；它不會呼叫模型。

### 直答組連結：`direct S2`

1. 拖選「擊之」，應立即看到 TS1 固定解釋，沒有選項或理由欄。
2. 對照提問組最後的解釋：整段字串應一致，沒有額外「沒錯」前綴或只給一組的錯因說明。
3. 點「看完了」，再選「帝甚不平」，應顯示帶示範標記的說明，不是提問組的問題。
4. 重新整理已開的互動，確認說明仍能恢復。

### 無 AI 組連結：`control S2`

1. 原文欄寬應與兩個 AI 組一致，沒有 AI 對話側欄或目標句底色。
2. 可看共同註解，不應出現模型回覆。
3. 不使用任何協助也能在最低閱讀時間後繼續。

### 三組共同檢查

- S2 未滿 180 秒不能繼續；重整不應把已讀時間歸零。
- 三組均不要求完成四個目標句；不要因「沒有 4/4 進度」判為故障。
- 可退出全螢幕、關頁；系統記錄事件，不阻止退出。現有全螢幕覆蓋層要求回到全螢幕才能繼續操作，若瀏覽器拒絕全螢幕需另外檢查相容性。
- 測試網頁重新整理與網路失敗時，留意錯誤訊息；不要把「按鈕有反應」等同於資料已成功儲存。

## 3. 再走完整流程

開啟 `http://localhost:3000`，新建一位測試受試者，依序完成 S1 → S2 → S4 → S3 → S5。這條路會實際分派組別，不能在網址加 `arm=...` 指定組別。

| 檢查 | 預期 |
|---|---|
| 不勾同意 | 不建立正常作答流程 |
| S1 交卷 | 依前測分層並分組；答案留在後端 |
| S2 不使用 AI | 180 秒後可繼續；只描述未使用，不因未使用刪除人員 |
| S3 | 頁首顯示「閱讀後測驗 1／2：同篇立即理解」；有原文、無註解、無 AI |
| S4 | 八題認知負荷量表；每題必須選擇 1–7，沒有預設答案；成功送出後才進入 S3 |
| S5 | 頁首顯示「閱讀後測驗 2／2：新篇遷移」；新篇章、無 AI、無註解 |
| 主流程結束 | 顯示延遲連結及開放／截止時間 |
| 提早開延遲連結 | 伺服器拒絕，不提前出題 |
| 已開放的 `S6` 假連結 | 從首次進入開始計測驗時間，提交後顯示完成 |
| 超過 +48 小時 | 拒絕新延遲作答，保留資料 |
| 題目倒數到零 | 已選答案隨交卷保存，未作答記為跳題 |
| 重複交相同測驗 | 不產生第二份作答，不覆寫第一次答案 |

測驗選項尚未交卷前，重新整理目前不會恢復前端草稿；這是已知限制，不是已驗證的自動存檔功能。

## 4. 檢查有沒有把答案送給受試者

僅在假資料測試時打開瀏覽器開發工具 → Network（網路），查看 `/api/state`、`/api/assist` 與 `/api/transcript` 的回應。

S2 提問互動應看到問題文字與輸入欄，沒有可見選項。S1／S3／S5／S6 測驗仍有選項。不得看到：`answerIndex`、`generatedAnswerIndex`、`rawResponse`、整份資料庫 participant 列或其他受試者 token。研究者端 `prompts:inspect` 可能顯示固定解釋，不能與受試者 API 混為一談。

測試時開開發工具、切頁可能留下視窗切換旗標，這些假資料不能用於研究分析。

## 5. 測試指令與證據範圍

```powershell
npm test
npm run typecheck
npm run validate:content
npm run smoke
npm run build
```

- `test`：規則、引擎、供應商假請求、儲存契約與流程邊界。PGlite 是嵌入式 PostgreSQL 測試環境；不等於真實 Supabase 多連線測試。
- `typecheck`：TypeScript 型別檢查，不測教學品質。
- `validate:content`：教材檢查；目前 48 個未簽核／未校勘錯誤是預期阻擋，不能自行翻旗標求通過。
- `smoke`：九位假受試者的離線主流程，走到等待延遲測驗，不呼叫付費模型。
- `build`：驗證可產生部署輸出，不代表已部署或實際瀏覽器操作通過。

無套件環境可用 `node scripts/verify-offline.mjs` 跑相容子集；它不包含 PGlite／真實資料庫整合測試，也不替代型別與正式建置。

真實模型測試需另設定已確認可用的 `LLM_MODEL` 與金鑰，在乾跑資料庫檢查。固定目標句不一定呼叫模型，所以不能只選「擊之」就聲稱已測 Gemini；必須測自由選取與需要模型判定的理由。

若要測真實 HTTP 路由，在示範伺服器運行時，另一個 PowerShell 視窗執行 `npm run check:http -- http://localhost:3000`。它只接受本機網址，使用 `demo:seed` 的假資料，會完成三組的一次互動及三個延遲測驗；重跑前先新增一批種子資料。這會改變假資料進度，不要與同一批手動測試混用。
